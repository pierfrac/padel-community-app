# Padel Community

Flutter app for organizing padel matches and community availability.

## Windows launcher

Double-click PADEL.bat to open the graphical launcher inspired by the portable TEO control panel. On first use, choose where Flutter and its caches should live: the default user profile, another disk (including an external drive), or an existing Flutter SDK.

The SDK, Flutter Web artifacts, Pub cache, configuration and logs are stored outside the repository by default under %LOCALAPPDATA%\PadelCommunity. This means redownloading the repository does not force another multi-gigabyte SDK download. Existing SDKs are reused when selected. The official Windows SDK is distributed as a ZIP; no smaller official 7z/tar.xz alternative was found. The launcher stores the archive outside TEMP, resumes interrupted downloads when supported, verifies the official SHA-256 checksum, and removes the ZIP after extraction. Only the Web artifacts are prepared for the preview, so Android Studio is not required.

If Git is missing on Windows, the launcher downloads the official portable MinGit package, verifies its SHA-256, and adds it only to the launch process. It does not install Git globally or modify the system PATH. The panel can run four independent Web preview sessions on stable local ports (normally 7357–7360). Each session gets its own working copy and logs, while the Flutter SDK and Pub cache are shared. Each session has Start and Stop controls; clicking its status reopens the browser URL, and closing the panel stops all managed sessions. They are four local UI instances, not yet four peers sharing synchronized data. Session 1 is configured for real Google sign-in once a Web OAuth Client ID is provided locally; Sessions 2–4 use synthetic player identities and need no email accounts. This test setup does not provide P2P transport or secure production admin authorization. Setup and diagnostics remain available under Advanced tools. See docs/WINDOWS_FLUTTER_SETUP.md and the [P2P-first architecture](docs/P2P_ARCHITECTURE.md).

### Command-line actions

PADEL.bat setup, web, format, analyze, test, build, check, doctor and clean are supported. Double-click without arguments opens the graphical panel.

A short-named source archive (`PADEL.zip`) is generated by GitHub Actions on each push to `develop`. Download the latest `PADEL` artifact from [the PADEL ZIP workflow](https://github.com/pierfrac/padel-community-app.-README-iniziale-non/actions/workflows/padel-zip.yml). Artifacts are retained for 14 days. See `docs/WINDOWS_FLUTTER_SETUP.md`.

## Current scope

The current screens are an interactive UI prototype and still use demonstration data. The P2P-first architecture is documented in [docs/P2P_ARCHITECTURE.md](docs/P2P_ARCHITECTURE.md): no mandatory central application server or authoritative central database. Google sign-in UI is being prepared for the first-session test; durable storage, peer-to-peer transport/synchronization, secure peer-verifiable admin authority, notifications and real booking integrations remain unimplemented. Local test roles must never authorize real admin actions.

## Validation

GitHub Actions is configured to format, analyze, test, and build the Web target. Until a run is confirmed successful, use the local launcher on Windows as the validation path; no successful CI or Windows execution is claimed by this README.
